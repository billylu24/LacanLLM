Data-cleaning review
- The old cleaning script had path errors when run from the project root and joined lines based on sentence-ending punctuation. That can incorrectly merge independent lines or split long Lacanian sentences.
- The new cleaner treats blank-line separated blocks as paragraph candidates, repairs hyphenated line breaks, removes obvious page numbers, filters very short/very long blocks, and records source metadata.
- Temporary validation run after tightening filters kept 51,460 paragraph candidates from 46 source txt files.
- Temporary validation paragraph length summary: min 120 chars, mean 456 chars, max 3507 chars.
- Remaining risk: the source text has encoding corruption markers such as mojibake characters. The cleaner records a mojibake_score per paragraph, but it does not automatically repair corrupted text. For publication-quality work, source files should be regenerated from PDFs or checked with a dedicated encoding/OCR cleanup pass.
- Remaining risk: footnotes and editorial notes still appear in some places. The current cleaner removes obvious numbered bracket notes and bibliographic boilerplate, but a publication workflow should still include manual sampling or an additional classifier/rule pass.

Training-logic review
- The original project used generated questions from Gemma and then fine-tuned Gemma on those question/passage pairs. This is workable as data distillation, but it should not be described as learning directly from human-authored QA unless manually validated.
- Sorting by output length as a quality score is weak. It tends to overselect long passages and may bias training toward verbose answers.
- A better training design is: preserve source metadata, generate candidate questions, sample/inspect a validation subset, filter malformed questions, split train/validation by source file, and evaluate with held-out passages/questions.
- With 12GB VRAM, 4-bit QLoRA on a 4B model is realistic. Full fine-tuning is not realistic on this machine.
- Training script update: run_pipeline.py now defaults to google/gemma-4-E4B-it, supports AutoProcessor/AutoTokenizer loading, creates train/validation JSONL splits, filters overlong passages before training, evaluates during training, writes adapter metadata, and can resume from the latest checkpoint with --auto-resume.
